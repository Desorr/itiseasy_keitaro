# Инструкции для работы с проектом

## Назначение и стек

Приложение создаёт кампании и управляет ими через Keitaro Admin API.
Backend — Python 3.11, FastAPI и httpx. Frontend — React, TypeScript и Vite.
Данные кампаний хранятся в Keitaro.

## Структура

- `backend/app/main.py` — HTTP-эндпоинты приложения и жизненный цикл API-клиента.
- `backend/app/keitaro.py` — запросы к Keitaro и обработка ошибок API.
- `backend/app/services.py` — создание, чтение и архивирование кампаний.
- `backend/app/schemas.py` — схемы запросов, ответов и серверная валидация.
- `backend/app/config.py` — настройки из окружения.
- `frontend/src/App.tsx` — форма создания и список кампаний.
- `frontend/src/api.ts` — HTTP-клиент фронтенда и типы данных.
- `frontend/src/style.css` — стили интерфейса.
- `backend/requirements.txt` — единственный файл Python-зависимостей.
- `docker-compose.yaml` — запуск backend и frontend.

## Правила изменений

- Решайте поставленную задачу без дополнительных функций и несвязанного рефакторинга.
- Сохраняйте асинхронные запросы backend: `async`/`await` и `httpx.AsyncClient`.
  Не добавляйте блокирующие сетевые вызовы в обработчики.
- Не добавляйте собственную БД, модели хранения, миграции или локальный серверный
  журнал операций без запроса пользователя.
- Проверяйте входные данные и на фронтенде, и на бэкенде. Ошибки формы показывайте
  рядом с полями, сообщения для пользователя пишите по-русски.
- Не заменяйте ошибки Keitaro сообщением об успехе. При частичном создании или
  неизвестном результате запроса сохраняйте информацию, необходимую для проверки результата.
- Не повторяйте автоматически изменяющие запросы после таймаута: операция могла
  выполниться в Keitaro. Сначала используйте чтение API для выяснения результата.
- При изменении API синхронно обновляйте серверные схемы и типы фронтенда.
- Добавляйте зависимости только по необходимости. Не создавайте дополнительные
  файлы requirements. Сохраняйте `frontend/package-lock.json` в проекте и обновляйте
  его вместе с npm-зависимостями.
- Если меняются запуск, конфигурация или поведение API, актуализируйте README.

## Особенности Keitaro

- Домен и источник выбираются из существующих объектов через API: первый активный
  в порядке ответа. Все новые кампании используют группу `test_markovskiy_group`: она
  получается через API, создаётся при отсутствии и сохраняется после удаления всех кампаний.
- Распределение трафика выполняет Keitaro. Первый поток фильтрует выбранную страну
  и перенаправляет на Google, второй направляет остальных посетителей на выбранный оффер.
- Удаление кампании означает перенос в архив. Не используйте
  `/campaigns/clean_archive` для удаления одной кампании: он очищает весь архив.
- Сохраняйте проверку принадлежности кампании приложению перед изменением или удалением.
- Все кампании, создаваемые агентом для разработки и проверок, должны иметь
  префикс `test_markovskiy_`.

## Проверки и запуск

Тесты и тестовая инфраструктура удалены по просьбе пользователя.
Не добавляйте и не запускайте тесты, не устанавливайте тестовые зависимости без его запроса.
Ruff и его конфигурация также удалены; не возвращайте их без запроса.
Обычная сборка и проверка синтаксиса разрешены.

- Сборка фронтенда: `cd frontend && npm run build`.
- Запуск приложения с пересборкой: `docker compose up -d --build`.
- Только frontend: `docker compose up -d --build --no-deps frontend`.
- Состояние контейнеров: `docker compose ps`.
- Локальное Python-окружение называется `venv`, а не `.venv`.

Для проверки небольших изменений используйте подходящую сборку или проверку кода.
Не создавайте реальные кампании только ради проверки оформления или текстов.
В результате работы сообщайте, что изменено и какие проверки действительно выполнены.

## Секреты

- `.env` содержит `KEITARO_BASE_URL` и `KEITARO_API_KEY`; не выводите секреты из него.
- Не добавляйте `.env`, API-ключи и другие секреты в Git, логи или сообщения пользователю.
- Обращайтесь к Keitaro с ключом только с backend. Не передавайте ключ во frontend.
