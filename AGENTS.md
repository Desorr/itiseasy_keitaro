# Инструкции для работы с проектом

## Назначение и стек

Менеджер кампаний через Keitaro Admin API. Backend — Python 3.11, FastAPI,
httpx.AsyncClient. Frontend — React, TypeScript, Vite. PostgreSQL 17 хранит
состояние приложения через SQLAlchemy AsyncEngine/AsyncSession и asyncpg;
миграции — Alembic. Трафик и маршрутизация работают в Keitaro.

Интерфейс, ошибки и валидация для пользователя — на английском.
Общение с пользователем — кратко по-русски. Имена кампаний/офферов не переводить.

## Структура

- `backend/app/main.py` — HTTP API, обработчики ошибок, lifecycle клиента и БД.
- `backend/app/keitaro.py` — HTTP-клиент, ошибки Keitaro, кэш справочников.
- `backend/app/services.py` — создание, проверки результата, архивирование.
- `backend/app/editor.py` — импорт, сохранение кампаний, черновики, доли и публикация.
- `backend/app/database.py` — подключение и модели campaigns/streams/offers/stream_offers.
- `backend/app/schemas.py` — схемы и серверная валидация.
- `backend/app/config.py` — настройки окружения.
- `backend/migrations` — миграции Alembic.
- `frontend/src/App.tsx` — создание, список кампаний, восстановление запроса создания.
- `frontend/src/CampaignEditor.tsx` — редактор потоков.
- `frontend/src/OfferPicker.tsx` — dropdown офферов редактора.
- `frontend/src/api.ts` — HTTP-клиент и TypeScript-контракты.
- `frontend/src/style.css` — оформление.
- `backend/requirements.txt` — единственный файл Python-зависимостей.
- `docker-compose.yaml` — PostgreSQL, backend и frontend.

## Правила изменений

- Решайте задачу без дополнительных функций и несвязанного рефакторинга.
- Сохраняйте асинхронные обращения к Keitaro и БД. Не добавляйте блокирующие
  сетевые вызовы в обработчики. Изменения схемы оформляйте миграциями Alembic.
- Не добавляйте отдельный журнал операций вне состояния публикации потока.
- Проверяйте формат входных данных на frontend и backend; ошибки формы — рядом
  с полями. При изменении API синхронно обновляйте Pydantic и TypeScript-типы.
- Не подменяйте ошибки Keitaro успехом. При частичном/неизвестном создании
  сохраняйте известный campaign_id и данные для выяснения результата.
- Не повторяйте автоматически изменяющие запросы после таймаута: сначала чтение.
  UUID в Idempotency-Key/alias не означает безопасный автоматический повтор POST.
- Не теряйте намерение публикации, черновики и ревизии при обработке ошибок.
- Новые зависимости добавляйте только по необходимости. Сохраняйте npm lock-файл.
- Актуализируйте README при изменении API, конфигурации, запуска или поведения.
- Не выполняйте коммит/push без запроса пользователя.

## Кампании и справочники

- Ответы списка, синхронизации списка и создания кампании используют CampaignSummary:
  только id/name/alias/state. Полный CampaignRead — внутренний снимок backend/БД;
  не возвращайте служебные ссылки и настройки кампании в этих ответах. Alias нужен
  для восстановления незавершённого создания. Список/sync возвращают массив,
  создание — один объект. Alias — адресный идентификатор, не секрет/API-ключ;
  не используйте его как средство авторизации.
- При входе сначала показывается список из БД, затем идёт фоновая синхронизация
  Keitaro. Refresh — принудительная синхронизация. Не возвращайте ожидание полного
  импорта перед показом сохранённого списка.
- При каждом открытии формы создания список активных офферов загружается свежим
  GET /api/offers из Keitaro API. Нет постоянного кэша офферов. Поиск локальный
  по цифрам ID, выбор из dropdown обязателен; при ошибке — Retry.
- При Create не добавляйте отдельную проверку GET /offers/{id}: пользователь
  отказался от неё. Backend проверяет формат ID и остальных полей; ошибки Keitaro
  при создании привязки сохраняются. offer_name — только отображаемые метаданные.
- Название — 5–255 символов, GEO — один существующий двухбуквенный код.
- Домен и источник — первые активные в порядке ответа API. Прогрев при входе
  и кэш до 60 секунд разрешены для доменов, источников и групп.
- При Create группы читаются свежим GET /groups?type=campaigns, независимо от
  прогрева. Приоритет FORTESTS, затем test_markovskiy_group. Если обе отсутствуют,
  создаётся только test_markovskiy_group. Обе группы ищутся в одном ответе GET,
  а не отдельными запросами по имени. Группы после архивирования не удаляются.
- Кампания сначала disabled, type=position, ip_ua, USD, cost_auto=true.
  Потоки создаются последовательно: Flow 1 — выбранный GEO и Google HTTP redirect;
  Flow 2 — остальные посетители, выбранный оффер 100%, без фильтров/лендингов.
- Сохраняйте проверки настроек до и после активации. Подтверждённый снимок
  сохраняется в БД без повторного импорта, не перезаписывая параллельно сохранённое
  состояние. Дополнительные потоки создаются только в Keitaro; имена при импорте
  сохраняются, фиксированные ID запрещены.
- При выборе существующей кампании очищайте поля/ошибки создания. Не показывайте
  сообщения формы в карточке кампании; сведения о неизвестном результате храните
  отдельно до сверки. В карточке нет строки GEO/Offers.
- Принадлежность приложению определяется alias tm_<16 hex>; проверяйте её перед
  изменением/архивированием. Удаление — архив через DELETE /campaigns/{id}.
  Никогда не используйте /campaigns/clean_archive для одной кампании.

## Редактор

- При каждом входе список пуст до Fetch streams from KT. Состояние в БД при этом
  не очищается. Автоматически загружать сохранённые потоки при открытии не нужно.
- Потоки с известными офферами, включая архив, идут сверху; без офферов — снизу.
  Внутри групп сохраняйте порядок Keitaro; fallback имени — Flow N по позиции.
- Add/Remove/Bring back создают черновик в БД. Remove сохраняет серую архивную
  строку с 0%; удаление последнего оффера разрешено, возможна публикация offers=[].
  Bring back восстанавливает привязку; объект оффера в Keitaro не удаляется.
- Дубликаты запрещены; для архивного оффера используется Bring back. Добавление
  и возврат в редакторе проверяют доступность/активность оффера через API.
- При наличии активных офферов целые доли дают 100%; остаток распределяется
  в стабильном порядке. Сортировка отображения не меняет порядок округления.
- Pin/Unpin закрепляет текущую долю без ручного ввода. Вне черновика — метаданные
  БД без публикации; внутри черновика отменяется вместе с ним. Удаление снимает
  pin, возврат без pin. Учитывайте allocation_error и блокировку публикации.
- Импорт принимает фактические доли без пересчёта и автоматического черновика.
  Пропавшие известные привязки архивируются. Имеющийся черновик сохраняется;
  внешние изменения вызывают конфликт, публикация блокируется до его разрешения.
- Push to KT изменяет только offers выбранного потока, с чтением до и после PUT.
  Сохраняйте ownership, expected_revision, транзакционные блокировки и HTTP 409.
- Намерение записи сохраняется до PUT. После timeout/краша нет повторной записи:
  чтение/синхронизация выясняет результат после 2*timeout+10 секунд от начала.
  Для missing-потока сохраняйте возможность отмены черновика после сверки.
- Не обещайте атомарный CAS Keitaro: внешняя гонка между чтением и PUT остаётся.

## Запуск и проверки

Тесты, тестовая инфраструктура и Ruff удалены по просьбе пользователя.
Не добавляйте/не запускайте тесты и не устанавливайте тестовые зависимости или
Ruff без его запроса. Разрешены сборка, проверка синтаксиса, миграции и ручные проверки.

Команды из корня:

- `npm --prefix frontend run build`.
- `venv/bin/python -m compileall -q backend/app backend/migrations`.
- `git diff --check`.
- `docker compose up -d --build` — полный запуск, миграции применяются автоматически.
- `docker compose up -d --build --no-deps frontend` — только frontend.
- `docker compose ps` — состояние контейнеров.

Локальное окружение — venv, не .venv. Frontend: localhost:8080, backend: localhost:8000,
PostgreSQL: 127.0.0.1:55432 (POSTGRES_PORT). Vite dev: localhost:5173.
Для небольших правок достаточно подходящей сборки/проверки кода. Не создавайте
реальные кампании ради оформления. Все кампании агента для функциональных проверок
имеют префикс test_markovskiy_; после проверки архивируйте созданные кампании.
Сообщайте только действительно выполненные проверки и их результаты.

## Секреты и Git

- Не выводите содержимое .env, API-ключи, POSTGRES_PASSWORD или DATABASE_URL в логи,
  Git и сообщения. Ключ Keitaro используется только на backend.
- Сохраняйте в Git исходники, миграции, Docker-конфигурацию, README, AGENTS.md,
  requirements.txt и package-lock.json. Локальные зависимости, сборки, кэши,
  логи, данные PostgreSQL и бэкапы игнорируются.
- .env.example разрешён только с шаблонными значениями без реальных секретов.
- Не удаляйте том postgres_data и не меняйте трекер/БД без соответствующей задачи.
